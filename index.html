DFA ตรวจความแข็งแรงของรหัสผ่าน

ออกแบบเครื่องจำกัดสถานะแบบกำหนดแน่นอน (DFA) ที่อ่านรหัสผ่านทีละตัวอักษร แล้วตัดสินว่าผ่านนโยบายความปลอดภัยหรือไม่ พร้อมตัวจำลองที่ดูการเปลี่ยนสถานะได้ทีละขั้น

1ปัญหาและนโยบายรหัสผ่าน

เว็บไซต์และแอปเกือบทุกแห่งต้องตรวจรหัสผ่านตอนสมัครสมาชิก งานนี้มองนโยบายรหัสผ่านเป็น ภาษา ชุดหนึ่ง แล้วสร้าง DFA ที่ยอมรับเฉพาะสตริงในภาษานั้น ข้อดีคืออ่านอินพุตรอบเดียวจากซ้ายไปขวา ใช้หน่วยความจำคงที่ และแสดงผลได้ทันทีขณะผู้ใช้พิมพ์

ภาษา Lstrong คือเซตของรหัสผ่าน w ที่ผ่านครบ 6 ข้อ

  1. ความยาวอย่างน้อย 8 ตัวอักษร (|w| ≥ 8)
  2. มีตัวพิมพ์ใหญ่ (U) อย่างน้อย 1 ตัว
  3. มีตัวพิมพ์เล็ก (L) อย่างน้อย 1 ตัว
  4. มีตัวเลข (D) อย่างน้อย 1 ตัว
  5. มีสัญลักษณ์ (S) อย่างน้อย 1 ตัว
  6. ไม่มีอักขระต้องห้าม (X) เช่น ช่องว่าง หรืออักษรไทย

2ตัวอักษรของเครื่อง (Σ)

แป้นพิมพ์มีอักขระเป็นร้อยตัว ถ้าใช้ทุกตัวเป็นสัญลักษณ์อินพุตตารางจะใหญ่เกินไป จึงแปลงอักขระแต่ละตัวเป็น คลาส ด้วยฟังก์ชัน classify ก่อน อักขระในคลาสเดียวกันทำให้เครื่องเปลี่ยนสถานะเหมือนกัน ผลการยอมรับจึงไม่เปลี่ยน

Σ = { U, L, D, S, X }

คลาสความหมายรหัส ASCIIตัวอย่าง
Uตัวพิมพ์ใหญ่65–90A B … Z
Lตัวพิมพ์เล็ก97–122a b … z
Dตัวเลข48–570 1 … 9
Sสัญลักษณ์ที่เหลือ33–126 ที่ไม่ใช่ U, L, D! @ # $ % _ -
Xอักขระต้องห้ามอื่น ๆ ทั้งหมดช่องว่าง, ก ข ค, อีโมจิ

3แนวคิดการออกแบบ: ต่อ DFA ย่อยเข้าด้วยกัน

เงื่อนไขแต่ละข้อเป็นภาษา Regular ที่ทำ DFA ได้ง่าย และภาษา Regular ปิดภายใต้ intersection จึงออกแบบ DFA ย่อยทีละเงื่อนไข แล้วรวมด้วย Product Construction สถานะของเครื่องรวมคือคู่อันดับของสถานะเครื่องย่อยทุกตัว

  • Mhas-x มี 2 สถานะ (no, yes) เปลี่ยนเป็น yes เมื่ออ่านคลาส x และอยู่ที่ yes ตลอด ใช้กับ x ∈ {U, L, D, S}
  • Mlen มี 9 สถานะ นับความยาว 0 ถึง 8+ พอถึง 8 แล้ววนอยู่ที่เดิม เพราะยาว 8 กับยาว 20 ผ่านเงื่อนไขเหมือนกัน

เครื่องรวม M = Mlen × Mhas-U × Mhas-L × Mhas-D × Mhas-S เพิ่มสถานะ q_dead สำหรับอักขระต้องห้าม เขียนส่วนที่เป็น has-x รวมกันเป็นเซต C ⊆ {U, L, D, S} ของคลาสที่เคยพบ สถานะจึงเขียนสั้น ๆ ได้ว่า q[C, n]

4นิยามเชิงรูปนัย M = (Q, Σ, δ, q₀, F)

Q  = { q[C, n] | C ⊆ {U,L,D,S}, n ∈ {0,1,…,7,8+} } ∪ { q_dead }
Σ  = { U, L, D, S, X }
q₀ = q[∅, 0]
F  = { q[{U,L,D,S}, 8+] }

δ(q[C, n], x) = q[C ∪ {x}, min(n+1, 8)]   เมื่อ x ∈ {U, L, D, S}
δ(q[C, n], X) = q_dead
δ(q_dead, x)  = q_dead                    สำหรับทุก x ∈ Σ

เครื่อง Accept สตริง w เมื่ออ่านครบแล้ว δ*(q₀, w) ∈ F ซึ่งเกิดได้กรณีเดียวคือเห็นครบ 4 คลาส ความยาวถึง 8 และไม่เคยเจออักขระต้องห้าม ทุกสถานะมีทางไปพอดี 1 ทางต่อ 1 สัญลักษณ์ จึงเป็น DFA ตามนิยาม

q_dead เป็น trap state เข้าแล้วออกไม่ได้ ต่อให้เคยผ่าน F มาแล้ว เช่น Abcdef1! ถ้าพิมพ์ช่องว่างต่อท้าย ผลก็เป็น Reject

ทำไมไปถึงได้แค่ 105: อ่านไป n ตัวจะพบคลาสได้ไม่เกิน n แบบ (|C| ≤ n) เช่น q[ULDS,2] ไม่มีทางเกิดขึ้น

ทำไมลดรูปเหลือ 77: ถ้ายังขาดอีก m คลาสก็ต้องอ่านอีกอย่างน้อย m ตัว สถานะที่มี C เดียวกันและ n ≥ 8 − m จึงทำงานเหมือนกันทุกประการ รวมเป็นสถานะเดียวได้ นับได้ 1 + 20 + 30 + 20 + 5 + 1 (dead) = 77

8เชื่อมโยงกับ NFA

เงื่อนไข "มีตัวเลขอย่างน้อย 1 ตัว" คือภาษา Σ*DΣ* เขียนเป็น NFA ได้เครื่องที่ "เดา" ว่าตัวเลขตัวไหนทำให้ผ่าน ที่ p₀ เมื่ออ่าน D มี 2 ทางเลือก คืออยู่ที่ p₀ ต่อ หรือย้ายไป p₁ แปลงเป็น DFA ด้วย Subset Construction ได้ดังนี้

เซตสถานะDΣ − {D}
→ {p₀}{p₀, p₁}{p₀}
* {p₀, p₁}{p₀, p₁}{p₀, p₁}

ได้ DFA 2 สถานะ คือ {p₀} = no และ {p₀,p₁} = yes ซึ่งก็คือ Mhas-D ในหัวข้อ 3 พอดี ยืนยันว่า NFA กับ DFA รู้จำภาษาได้เท่ากัน งานนี้เลือก DFA เพราะแต่ละขั้นดูตารางครั้งเดียว ไม่ต้องติดตามเซตของสถานะ

9โค้ดตัวอย่างการนำไปใช้ด้วย Python

โค้ดสร้างตาราง δ อัตโนมัติจากนิยามในหัวข้อ 4 โดยไล่หาสถานะที่ไปถึงได้จาก q₀ มีคลาส DFA ที่นำไปใช้กับเครื่องอื่นได้ มีฟังก์ชันลดรูปแบบ partition refinement และชุดทดสอบ 13 ข้อ ใช้ไลบรารีมาตรฐานของ Python เท่านั้น บันทึกเป็นไฟล์ dfa_password.py แล้วรันได้เลย

"""DFA ตรวจความแข็งแรงของรหัสผ่าน (ใช้ Python มาตรฐานเท่านั้น)"""
import sys

SIGMA = "ULDSX"
MAX_LEN = 8
DEAD = "q_dead"


def classify(ch):
    """แปลงอักขระเป็นคลาส U, L, D, S หรือ X"""
    c = ord(ch)
    if 65 <= c <= 90:
        return "U"
    if 97 <= c <= 122:
        return "L"
    if 48 <= c <= 57:
        return "D"
    if 33 <= c <= 126:
        return "S"
    return "X"


class DFA:
    def __init__(self, sigma, start, accepting, step):
        self.sigma, self.start, self.accepting = sigma, start, accepting
        self.delta = {}            # สร้างตาราง δ จากสถานะที่ไปถึงได้
        todo, seen = [start], {start}
        while todo:
            q = todo.pop()
            for x in sigma:
                r = step(q, x)
                self.delta[(q, x)] = r
                if r not in seen:
                    seen.add(r)
                    todo.append(r)
        self.states = seen

    def is_accepting(self, q):
        return self.accepting(q)

    def run(self, symbols):
        q, path = self.start, [self.start]
        for x in symbols:
            q = self.delta[(q, x)]
            path.append(q)
        return q, path

    def minimize(self):
        """partition refinement: คืนจำนวนสถานะหลังลดรูป"""
        part = {q: self.is_accepting(q) for q in self.states}
        while True:
            sig = {q: (part[q], tuple(part[self.delta[(q, x)]] for x in self.sigma))
                   for q in self.states}
            ids = {s: i for i, s in enumerate(sorted(set(sig.values()), key=repr))}
            new = {q: ids[sig[q]] for q in self.states}
            if len(set(new.values())) == len(set(part.values())):
                return len(set(new.values()))
            part = new


def name(q):
    if q == DEAD:
        return DEAD
    c, n = q
    return "q[%s,%s]" % (c or "-", "8+" if n >= MAX_LEN else n)


def step(q, x):
    if q == DEAD or x == "X":
        return DEAD
    c, n = q
    c = "".join(k for k in "ULDS" if k in c or k == x)
    return (c, min(n + 1, MAX_LEN))


M = DFA(SIGMA, ("", 0), lambda q: q != DEAD and len(q[0]) == 4 and q[1] >= MAX_LEN, step)


def check(password, verbose=False):
    q, path = M.run(classify(ch) for ch in password)
    if verbose:
        print("สตริง: %r" % password)
        print("ขั้น  อักขระ คลาส  สถานะ")
        print("%4d  %-6r %-5s %s" % (0, "", "", name(path[0])))
        for i, ch in enumerate(password, 1):
            print("%4d  %-6r %-5s %s" % (i, ch, classify(ch), name(path[i])))
    return M.is_accepting(q)


TESTS = [
    ("", False), ("abc", False), ("abcdefgh", False), ("Abcdefg1", False),
    ("Abc1!", False), ("Abcdef1!", True), ("Ab1!xyz9", True), ("Abc def1!", False),
    ("Abcdef1!x", True), ("Abcdef1! ", False), ("P@ssw0rd2026", True),
    ("รหัสผ่านAb1!xyz", False), ("ABCDEFG1!", False),
]


def run_tests():
    ok = 0
    for w, exp in TESTS:
        got = check(w)
        ok += got == exp
        print("%-4s %r" % ("ผ่าน" if got == exp else "FAIL", w))
    print("ผลรวม: %d/%d" % (ok, len(TESTS)))


def show_table():
    print("ตามนิยาม      :", 16 * 9 + 1)
    print("ไปถึงได้จริง   :", len(M.states))
    print("หลังลดรูป      :", M.minimize())


if __name__ == "__main__":
    if "--test" in sys.argv:
        run_tests()
    elif "--table" in sys.argv:
        show_table()
    else:
        pw = input("รหัสผ่าน: ")
        print("ผล:", "ACCEPT (แข็งแรง)" if check(pw, True) else "REJECT")

10สรุปและข้อจำกัด

  • นโยบายรหัสผ่านทั่วไปเป็นภาษา Regular ตรวจด้วย DFA ได้ รอบเดียว เวลา O(|w|) หน่วยความจำคงที่
  • แยกเงื่อนไขเป็น DFA ย่อยแล้วรวมด้วย Product Construction ทำให้ออกแบบและตรวจได้ทีละส่วน เพิ่มเงื่อนไขใหม่ก็คูณ DFA ย่อยเพิ่ม
  • การจัดอักขระเป็นคลาสทำให้ Σ เหลือ 5 ตัว ตารางมี 105 × 5 = 525 ช่อง
  • ข้อจำกัด: เงื่อนไขอย่าง "ห้ามซ้ำกับชื่อผู้ใช้" ต้องใช้ข้อมูลภายนอก จึงตรวจนอก DFA ส่วนการเช็กรายการรหัสที่รั่วไหลทำเป็น DFA ได้ในทฤษฎีแต่สถานะมหาศาล ในทางปฏิบัติใช้ hash set ดีกว่า
  • รหัสที่ผ่าน DFA นี้แค่ ตรงตามนโยบาย ไม่ได้แปลว่าเดายาก เช่น Password1! ก็ผ่าน ระบบจริงควรตรวจรหัสยอดนิยมร่วมด้วย
